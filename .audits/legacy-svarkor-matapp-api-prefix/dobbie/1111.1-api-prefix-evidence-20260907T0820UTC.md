## What the card asked (wrapper `show` returns title/status only; scope = title)
Make API_BASE prefix-aware so the frontend's `api/stores` request works when the
app is served under /matapp/ — a TDD code task on the frontend JS.

## Root cause (VERIFIED live this turn)
The renderer's nginx serves matapp at https://sibbamala.com/matapp/ and STRIPS
the /matapp prefix before proxying to the FastAPI backend (same pattern as
hotell/bibliotek/rocket — prior art commits ad17229, fde0ee5, e082a54 in the
hosting repo). The frontend static/js/utils/api.js shippers `const API_BASE=''`,
so stores.js fetches a bare `/api/stores` at the origin root where nginx has no
location. Live curl (this turn):
  GET https://sibbamala.com/api/stores        -> 404   (old behaviour: broken)
  GET https://sibbamala.com/matapp/api/stores -> 200   [willys,ica,coop] (works)

## Fix (surgical, in static/js/utils/api.js)
Replace the hardcoded empty base with a pure, testable prefix detector driven by
window.location.pathname — prefix-aware (works at /matapp and at root ""), no
hardcoded "/matapp", robust to the app moving prefix:
  function resolveApiBase(pathname){ const seg=(pathname||'').split('/')[1]; return seg?'/'+seg:''; }
  const API_BASE = resolveApiBase(window.location.pathname);
=> under /matapp/: API_BASE="/matapp" -> fetches /matapp/api/stores -> 200.
