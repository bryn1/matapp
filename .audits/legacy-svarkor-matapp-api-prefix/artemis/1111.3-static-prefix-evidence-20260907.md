## What the card asked
Make the script/link static references in `apps/matapp/templates/index.html` prefix-aware.
Currently 7 refs are hardcoded absolute `/static/...`, which 404 under the `/matapp/` deployment
because the renderer's nginx has no location at the origin root for /static — it serves the app
under /matapp and proxies `/matapp/static/...` to the backend, whose FastAPI mounts static at /static.

## Root cause (VERIFIED live this turn)
- `GET https://sibbamala.com/static/<asset>?v=...`        -> 404  (bare path = origin root, no location -> THE bug)
- `GET https://sibbamala.com/matapp/static/<asset>?v=...` -> 200  (fixed path) — all 7 assets
- `GET https://sibbamala.com/matapp` -> 301 -> `/matapp/` (canonical URL always carries trailing slash)
This is exactly the sibling-scope dobbie flagged in 1111.1 evidence (lines 60-67): "the PAGE still
won't fully paint until those static references are also made prefix-aware (same pattern)."

## The fix (surgical — only the 7 static-ref lines)
Switch the 7 static refs from absolute `/static/...` to RELATIVE `static/...` (the established ai-os
pattern already in this repo: `apps/ai-os/index.html` uses `static/css/app.css`). Under `/matapp/`
these resolve to `/matapp/static/...` (live 200 for all 7); at root they resolve to `/static/...`
(local dev, mounted StaticFiles -> 200). No hardcoded `/matapp`, robust to the prefix, consistent
with the no-hardcode / derive-from-path spirit of sibling 1111.1. The `?v=` cache-busters from
1111.2 are preserved verbatim (each still == real sha256[:8] of its asset on disk — check E).

  <link rel="stylesheet" href="/static/css/base.css?v=1e554f53">   ->   static/css/base.css?v=1e554f53
  <link rel="stylesheet" href="/static/css/components.css?v=1273106d"> -> static/css/components.css?v=1273106d
  <link rel="stylesheet" href="/static/css/responsive.css?v=d24ae63c"> -> static/css/responsive.css?v=d24ae63c
  <script src="/static/js/utils/api.js?v=2920e3ec"></script>      ->   static/js/utils/api.js?v=2920e3ec
  <script src="/static/js/ui/stores.js?v=0b59aafb"></script>      ->   static/js/ui/stores.js?v=0b59aafb
  <script src="/static/js/ui/menu.js?v=87e618dd"></script>        ->   static/js/ui/menu.js?v=87e618dd
  <script src="/static/js/app.js?v=4ab6bd82"></script>            ->   static/js/app.js?v=4ab6bd82

## Common pitfalls AVOIDED
- Did NOT hardcode `/matapp` (would break local dev at root + be inconsistent with 1111.1's
  derive-from-path pattern; relative approach works at /matapp AND root).
- Did NOT use a JS-in-head runtime rewrite for <link> — CSS links must carry the right URL at
  parse time (before first paint); a relative href already resolves correctly with zero JS.
- Preserved all 7 `?v=` cache-busters exactly (they are the whole point of 1111.2); only the
  leading `/` of `/static` was dropped.
