## What the card asked
Stamp a `?v=` cache-buster onto the static references in `apps/matapp/templates/index.html`.
Why: the app is served behind Cloudflare, which CDN-caches static assets for ~4 hours
(header cf-cache-status visible on the live site). Without a per-content URL stamp, a
deploy is INVISIBLE — browsers and the CDN edge keep serving the stale CSS/JS for hours
(Willys's very real predecessor incident: futurecraft rendered a black page for days from
4h-stale JS at the exact URLs the page imports — audit-2162/portfolio/fix-futurecraft-deploy.md).

## The fix (surgical — only the 7 static-ref lines in index.html)
`index.html` currently ships 7 un-stamped static refs (3 CSS + 4 JS). Each now carries
`?v=<sha256[:8]>` computed from the asset's CURRENT content, matching the repo's existing
cache-buster convention verbatim (apps/ai-os `?v=ead58f6a`, apps/futurecraft `?v=a6b61add`):

  <link rel="stylesheet" href="/static/css/base.css?v=1e554f53">
  <link rel="stylesheet" href="/static/css/components.css?v=1273106d">
  <link rel="stylesheet" href="/static/css/responsive.css?v=d24ae63c">
  <script src="/static/js/utils/api.js?v=2920e3ec"></script>
  <script src="/static/js/ui/stores.js?v=0b59aafb"></script>
  <script src="/static/js/ui/menu.js?v=87e618dd"></script>
  <script src="/static/js/app.js?v=4ab6bd82"></script>

Mechanism: the `?v=` query is part of BOTH the browser cache key and the CDN cache key.
A changed asset (new sha) => new URL => cache miss at browser AND edge -> fresh bytes on
deploy. Unchanged assets keep the same URL => still cached => no wasted refetch. This is
exactly why the fleet standard is per-content hash, not a manual date bump.

## Operational note for the deployer (IMPORTANT — read before merging)
These are STATIC content-hash stamps in a statically-served FileResponse (app.main root()
returns templates/index.html byte-for-byte; no templating). So:
  * When you EDIT one of the 7 assets in a future deploy, you MUST recompute and bump that
    asset's `?v=` stamp in index.html too, or its old URL (old hash) stays cached and your
    change is invisible again. Recompute with:  sha256sum static/<asset> | cut -c1-8
  * The verify script's B/C checks make this failure LOUD: if a deploy's stamp no longer
    equals the asset's real sha, verify fails — run it on every matapp asset deploy.
If automatic per-deploy busting is preferred later (no manual bump), a follow-up could move
index.html to a Jinja2 template that injects hashes at startup — OUT OF SCOPE for this card,
flagged for the render-fix owner.
